## 二、易错点 / 重点

5. **moved-from 后解引用**
   - 表现：问「打印最后一个不会报错吗」（`ptr_a->a()`）。
   - 结论：`std::move` 后 `unique_ptr` 为 `nullptr`，`ptr->member()` 解引用空指针 = UB；须先 `if (ptr)`。

6. **sizeof 与「对象存活 / 值」无关**
   - 表现：问「可是它不已经被移走了吗」。
   - 结论：move 只改内部值（指针 → `nullptr`），对象仍存活、大小由类型编译期固定；`sizeof` 看类型不看值。

7. **`delete` vs `delete[]` 配对**
   - 表现：自测中答「可能会崩溃」，未点破根因。
   - 结论：`unique_ptr<A>` 用 `delete`；管 `new A[]` 必须 `unique_ptr<A[]>`（用 `delete[]`）；不配对 = UB。

8. **函数指针基础薄弱**
   - 表现：问「函数指针是什么」「为什么 `std::fclose` 是函数指针」「没加 `&` 也能行」。
   - 结论：函数名在表达式位置自动 decay 为函数指针；`decltype(函数名)` 给**函数类型**，`decltype(&函数名)` 才给**函数指针类型**。

9. **deleter 的调用约定与形态**
   - 表现：问「谁给这个表达式传参」，并尝试写 `(FILE*, int)` 两参数的 deleter。
   - 结论：`unique_ptr` 以 `deleter(get())` 调用，只传一个指针；额外状态用**捕获**，不能加参数。

10. **deleter 的 size 成因**
    - 表现：问函数指针 deleter 为何 16、有状态 lambda 为何 8+捕获。
    - 结论：EBO 只压**空类**；函数指针是标量占 8，有状态闭包按其捕获成员计。

11. **`use_count()` 不数 weak_ptr**
    - 表现：问「这不应是2吗」（`w = a` 之后 `w.use_count()`）。
    - 结论：`use_count()` 返回**强计数**，只数 shared_ptr；`w = a` 只加弱计数，故为 1；`lock()` 生成 shared_ptr 后才变 2。

12. **`lock()` 的含义**
    - 表现：问「让它提升为 shared_ptr?」。
    - 结论：`lock()` 原子地「检查对象存活 + 返回共享所有权的 shared_ptr」，不修改 `w` 本身；存活返回非空，已销毁返回空。

13. **弱计数与控制块释放时机**
    - 表现：要求「弱计数再讲一下」。
    - 结论：强计数==0 → 对象析构；强计数==0 且 弱计数==0 → 控制块释放。无公开 API 读弱计数；`make_shared` 下 weak_ptr 存活会延迟整块内存释放。

14. **`shared_from_this()` 是否加计数**
    - 表现：问「不是会提升为 shared_ptr，然后引用计数加一了吗」。
    - 结论：对，`shared_from_this() == weak_this.lock()`，返回 shared_ptr 即 +1；加在**返回的新句柄**上，`weak_this` 不变。

15. **返回的是否「原本那个 shared_ptr」**
    - 表现：问「意思返回的不是本身的 shared_ptr?」。
    - 结论：返回**新句柄**（`&f != &s`），但 `get()` 相同、共享同一控制块（计数 2）。

16. **CRTP 概念**
    - 表现：问「crtp 是什么」。
    - 结论：派生类把自己作为模板实参传给基类的惯用法（`D : Base<D>`）；用于编译期多态 / mixin，无 vtable。

17. **static 成员归属**
    - 表现：问「这每个对象共享一份吗」。
    - 结论：static 属于类、不属对象 → 同类型对象共享一份；CRTP 下每个派生类各得一份独立变量。

18. **别名构造函数的用途**
    - 表现：问「别名构造函数有什么用」。
    - 结论：解耦「指向」与「拥有」——指向成员而拥有整个对象（保父对象存活）、是 `static_pointer_cast` 等的底层机制、keep-alive 句柄。

19. **PIMPL 析构为何要写到 .cpp**
    - 表现：问「`Widget::~Widget() = default;` 为什么 Impl 在此处才完整、才能实例化 delete」。
    - 结论：`unique_ptr<Impl>` 析构需 `Impl` 完整类型；`= default` 决定析构**定义点**，必须落在 `Impl` 完整可见处（.cpp、且 `Impl` 定义之后），否则报 incomplete type。

20. **QPointer 的定位**
    - 表现：问「QPointer 是什么、有什么用」。
    - 结论：非拥有型守卫指针，仅限 QObject 子类；对象被 delete 时自动置 null。不持有所有权、不能提锁、不替代 parent-child。

21. **Qt 智能指针家族**
    - 表现：问「Qt 有没有独占所有权的智能指针」。
    - 结论：有——`QScopedPointer`（对标 `unique_ptr`、不可拷贝、纯作用域）、`QScopedArrayPointer`；共享用 `QSharedPointer`，弱观察 QObject 用 `QPointer`。

22. **lambda 按值捕获局部 QPointer 的生命周期**
    - 表现：问「guard 是局部变量，出函数不就被销毁了？」。
    - 结论：`[guard]` 是**值捕获**，闭包内是句柄副本，随闭包存活；`[&guard]` 才会悬垂。副本带析构回连，对象死时所有句柄一起置 null。

23. **判活判的是副本**
    - 表现：问「`if (guard)` 判的是副本吧，又不是原来的变量」。
    - 结论：副本是「指向同一 `w` 的第二个句柄」，不是 `w` 的副本；`if (guard)` 判的是对象 `w` 存活，而非句柄变量本身。

24. **裸指针 vs QPointer**
    - 表现：问「为什么不直接用 `QWidget* guard`」。
    - 结论：裸指针对象销毁后地址不变 → 悬垂、判活失效；QPointer 有析构回连，会置 null。代价是更大且需登记。
