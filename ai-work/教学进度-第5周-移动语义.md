## 二、易错点 / 重点

- 模块 2（std::move 本质 + 移动构造/赋值）：已讲；用户就 `move(T&&)` 形参是否转换、`const` 左值、`const T&` 为何绑右值连续追问（非答错，属细节深挖）。自测「缺置空的移动构造」→ 用户答「没置空 data → 双重释放」**正确**，模块 2 判定已掌握。
- 模块 1（左值/右值/值类别）：用户总结「主要不要把值类别和类型搞混」→ 抓到核心点。
- **易错点 25（实测答错）**：自测 `int&& r = 5; f(r);` 走哪个重载 → 用户答 **f(int&&)**，依据「r 的类型是 int&&」。
  - 根因：**把声明类型当归值类别**。正确：表达式 `r` 的值类别是 **lvalue**（有名字），故只能绑 `int&`，正确答案 **f(int&)**；要调 `f(int&&)` 须写 `f(std::move(r))`。
  - 状态：重测复述为「由值类别决定」，方向正确，仅术语说成「被调用者」（应为**实参**）→ 判定为已掌握，易错点 25 仍留待巩固以复习。
- **易错点 26（实测答错）**：推导 `move_if_noexcept(declval<C&>())` 返回类型，C 为 `C(const C&)=delete; C(C&&) noexcept(false);`。用户写条件 **`!true && false`**，即把 `is_nothrow_move_constructible_v<C>` 当成了 `true`。
  - 根因：**误判移动构造的 noexcept 属性**。C 的移动构造是 `noexcept(false)`，故 `is_nothrow_move_constructible_v<C> = false`，第一项应为 **`!false = true`**，正确条件 **`true && false = false`**。
  - 结论侥幸正确：因 `&& false` 恒为 `false`，最终仍返回 `C&&`；但中间依据错，换一种定义（如可拷贝）就会翻车 → 记待巩固。
- 模块 3（正向记录）：用户复述「`noexcept` 运算符判断任意表达式是否（可能）抛」→ 核心正确；仅需精确返回值方向（`noexcept(expr)` 为 `true` 表示**不抛**，为 `false` 才表示可能抛）。模块 3 仍标待巩固（易错点 26 待复习）。

## 三、待巩固（下次开场优先复述）

- 值类别 ≠ 类型；具名右值引用是左值（模块 1 · 易错点 25）
- `is_nothrow_move_constructible_v<T>` 的取值由**移动构造的 noexcept 规格**决定（`noexcept(false)` → `false`）；写 `move_if_noexcept` 的条件时别把 `!` 后的值搞反（模块 3 · 易错点 26）
